Hata Yönetimi & Rate Limit

OzyConnect API, standart HTTP durum kodları ile tutarlı JSON hata yanıtları döner. Bu bölüm, üretim ortamında sağlam bir entegrasyon için uygulamanız gereken hata işleme kurallarını anlatır.

Hata Yanıt Formatı

Tüm hata yanıtları aşağıdaki ortak yapıyı takip eder:

json{
  "error": true,
  "code": "VALIDATION_FAILED",
  "message": "Geçersiz parametre: 'price' negatif olamaz",
  "details": {
    "field": "price",
    "value": -10
  },
  "request_id": "req_8a1f2c09"
}

İpucu. Destek taleplerinizde request_id alanını iletmeniz, bizim için sorunu çok daha hızlı teşhis etmemizi sağlar.

HTTP Durum Kodları

Kod Anlam Ne Yapmalısınız?
200 OK İstek başarılı. Yanıtı işleyebilirsiniz.
201 Created Kaynak oluşturuldu. Yanıttaki id değerini saklayın.
400 Bad Request Geçersiz istek gövdesi veya parametreleri. Parametre ve JSON yapısını doğrulayın.
401 Unauthorized Kimlik doğrulama başarısız. Key/Secret, imza, timestamp ve nonce değerlerinizi kontrol edin.
403 Forbidden Token doğru ama yetkisi yok. Permission scope (izinler) ayarlarınızı kontrol edin.
404 Not Found Kaynak bulunamadı. URL, ID, SKU değerini doğrulayın.
409 Conflict Çakışma (örn. aynı SKU zaten var). Önce kaynağın var olup olmadığını kontrol edin.
422 Unprocessable Validasyon hatası. details.field alanındaki hataları düzeltin.
429 Too Many Requests Rate limit aşıldı. Retry-After süresini bekleyip tekrar deneyin.
500 Internal Error Sunucu tarafında beklenmeyen hata. Kısa süre sonra tekrar deneyin; sürerse destek ile iletişime geçin.
502 / 503 / 504 Geçici altyapı sorunu veya bakım. Exponential backoff ile otomatik yeniden deneme yapın.

İş Mantığı Hata Kodları

HTTP durumuna ek olarak, code alanı daha spesifik bir hata türü taşır. Sık karşılaşılan kodlar:

Kod Açıklama

Rate Limit

Sistem, her API Key için ayrı ayrı rate limit uygular. Varsayılan limit 10 istek / saniye'dir ve yoğun kullanım senaryolarında yükseltilebilir.

Rate Limit Header'ları

Her yanıtta aşağıdaki başlıklar döner:

HeaderAçıklama
X-RateLimit-LimitSaniye başına izin verilen maksimum istek.
X-RateLimit-RemainingŞu anki saniye penceresinde kalan istek hakkı.
X-RateLimit-ResetPencere sıfırlanana kadar kalan saniye.
Retry-After429 yanıtlarında, kaç saniye sonra tekrar deneyebileceğinizi belirtir.

Önemli. 429 alındığında hemen tekrar denemek limitin devam etmesine yol açar. Mutlaka Retry-After süresini bekleyin.

Önerilen Yeniden Deneme (Retry) Stratejisi

Üretimde sağlam bir entegrasyon için aşağıdaki exponential backoff stratejisini uygulayın:

DurumÖneri
408, 502, 503, 504Maksimum 5 deneme, 1s → 2s → 4s → 8s → 16s bekleme.
429Retry-After değerini baz alın, üzerine %20 jitter ekleyin.
500En fazla 2 kez tekrar deneyin; sürerse logla ve bildir.
4xx (yukarıdakiler hariç)Yeniden denemeyin. İstek içeriği hatalı.

Örnek Retry Fonksiyonu (PHP)

PHPfunction callWithRetry(callable $fn, int $maxAttempts = 5): array
{
    $attempt = 0;
    $delay   = 1; // saniye

    while (true) {
        $attempt++;
        try {
            return $fn();
        } catch (OzyApiException $e) {
            $status = $e->getStatus();
            $retryable = in_array($status, [408, 429, 500, 502, 503, 504]);

            if (!$retryable || $attempt >= $maxAttempts) {
                throw $e;
            }

            $wait = $status === 429
                ? ($e->getRetryAfter() ?? $delay)
                : $delay;

            // %20 jitter ile backoff
            sleep(intval($wait * (0.9 + (mt_rand() / mt_getrandmax()) * 0.2)));
            $delay *= 2;
        }
    }
}

Idempotency (Tekrarlı Çağrı Güvenliği)

Kritik yazma operasyonlarında (ör. sipariş oluşturma) ağ kopması sonrası tekrar denemelerin yan etkisi olmaması için Idempotency-Key başlığı kullanabilirsiniz:

httpPOST /api/v1/products
Authorization: Bearer oxy_abc:sig:ts:nonce
Content-Type: application/json
Idempotency-Key: 6f1e2a88-35b4-4e56-9a39-5c47e1cbe0b2

Aynı key ile gönderilen istekler 24 saat boyunca aynı yanıtı döner ve yeni bir kayıt yaratmaz.

Sık Karşılaşılan Hatalar ve Çözümleri

401 AUTH_SIGNATURE_MISMATCH — En sık sebep: imzalanan mesajda endpoint'e query string eklenmiş veya \n karakterleri yerine \\n yazılmıştır. Mesajı method + endpoint + timestamp + nonce (tam olarak bu sıra ve sadece \n ile) oluşturun.

401 AUTH_EXPIRED_TIMESTAMP — Sunucunuzun saati kaymıştır. Linux'ta timedatectl status, Windows'ta w32tm /query /status ile NTP senkronunu doğrulayın.

403 PERMISSION_DENIED — Token'ınızın scope'u yetersizdir. Panelden Ayarlar → API Tokens ekranında izin kapsamını güncelleyin.

429 RATE_LIMIT_EXCEEDED — Toplu işlerde istekleri küçük parçalara bölün ve yukarıdaki retry stratejisini uygulayın. Yüksek limit talebi için destek ekibine başvurun.

422 VALIDATION_FAILED — details alanını okuyup kullanıcınıza anlamlı geri bildirim gösterin. Örneğin fiyat negatifse arayüzde fiyat alanını vurgulayın.
