Kimlik Doğrulama

OzyConnect REST API tüm isteklerde HMAC-SHA256 tabanlı imzalı kimlik doğrulama kullanır. Bu sayede API Secret değeriniz ağ üzerinden asla iletilmez, sadece her istekte anlık olarak hesaplanan imza gönderilir.

1. Token Oluşturma

Panel yöneticiniz, OzyConnect üzerinden size özel bir API Key & Secret çifti oluşturur. Bu işlem panelde şu adımla yapılır:

  1. Panele Giriş Yapın

    Sağ üstteki kullanıcı menüsünden Ayarlar sayfasına gidin.

  2. API Tokens Sekmesini Açın

    Ayarlar → API Tokens ekranından Yeni Token Oluştur butonuna tıklayın.

  3. Yetkileri ve Limitleri Belirleyin

    Token adı, izinler (products:read, orders:* vb.), IP whitelist, rate limit ve son kullanma tarihini belirleyin.

  4. Secret Değerini Kaydedin

    Oluştur butonuna bastığınızda API Secret yalnızca bir kez görüntülenir. Güvenli bir yerde saklayın — kayıp durumunda yeniden üretmeniz gerekir.

Uyarı. Secret değerini kaynak kodunuza, Git deponuza veya genel loglarınıza asla yazmayın. Üretimde .env, secret manager veya vault benzeri yapılar kullanın.

2. Token Yapısı

Size teslim edilen her token aşağıdaki alanlara sahiptir:

Alan Örnek Açıklama
API Key oxy_abc123def456 Genel kimlik. Her istekte açıkça gönderilir.
API Secret s3cr3t_xxxxxxxxxxxxxxxx Yalnızca imzalamada kullanılır. Hiçbir zaman iletilmez.
Permissions products:* Scope bazlı yetkilendirme. * wildcard desteklenir.
IP Whitelist 185.1.2.3 Sadece bu IP'lerden gelen istekler kabul edilir.
Rate Limit 10 / sn Saniye başı maksimum istek.
Expiration 2027-01-01 İsteğe bağlı son kullanma tarihi.

3. İmza Algoritması

Her istek için aşağıdaki adımları uygulayarak bir HMAC-SHA256 imzası üretmeniz gerekir:

3.1 — İmzalanacak Mesajı Oluşturun

Mesaj dört parçanın \n karakteriyle birleştirilmesinden oluşur:

format{HTTP_METHOD}\n{ENDPOINT_PATH}\n{TIMESTAMP}\n{NONCE}
Parça Açıklama
HTTP_METHODBüyük harfle HTTP metodu: GET, POST, PUT, DELETE.
ENDPOINT_PATHSorgu parametreleri hariç endpoint yolu. Örn: /api/v1/products
TIMESTAMPUnix timestamp (saniye). Mevcut zamandan ±5 dakika içinde olmalıdır.
NONCERasgele 16 karakterli hex string. Her istekte farklı olmalıdır.

3.2 — HMAC-SHA256 ile İmzalayın

Oluşturduğunuz mesajı API Secret ile imzalayın ve hex formatında çıktı alın.

3.3 — Authorization Header'ını Oluşturun

headerAuthorization: Bearer {API_KEY}:{SIGNATURE}:{TIMESTAMP}:{NONCE}
Content-Type: application/json

4. İmza Üretim Örneği

Aşağıdaki örnekler GET /api/v1/products isteği için geçerli bir imza üretir.

PHP<?php
$apiKey    = 'oxy_abc123def456';
$apiSecret = 'your_api_secret_here';

$method   = 'GET';
$endpoint = '/api/v1/products';
$timestamp= time();
$nonce    = bin2hex(random_bytes(8));

$message   = "{$method}\n{$endpoint}\n{$timestamp}\n{$nonce}";
$signature = hash_hmac('sha256', $message, $apiSecret);

$auth = "Bearer {$apiKey}:{$signature}:{$timestamp}:{$nonce}";

$ch = curl_init('https://panel.musteri.com/api/v1/products');
curl_setopt_array($ch, [
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_HTTPHEADER     => [
        "Authorization: {$auth}",
        'Content-Type: application/json',
    ],
]);
$response = curl_exec($ch);
echo $response;
Node.jsconst crypto = require('crypto');

const apiKey    = 'oxy_abc123def456';
const apiSecret = 'your_api_secret_here';

const method    = 'GET';
const endpoint  = '/api/v1/products';
const timestamp = Math.floor(Date.now() / 1000);
const nonce     = crypto.randomBytes(8).toString('hex');

const message   = `${method}\n${endpoint}\n${timestamp}\n${nonce}`;
const signature = crypto.createHmac('sha256', apiSecret)
                         .update(message)
                         .digest('hex');

const auth = `Bearer ${apiKey}:${signature}:${timestamp}:${nonce}`;

fetch('https://panel.musteri.com/api/v1/products', {
    headers: {
        'Authorization': auth,
        'Content-Type': 'application/json',
    },
})
.then(r => r.json())
.then(console.log);

api_key    = 'oxy_abc123def456'

C#using System;
using System.Net.Http;
using System.Security.Cryptography;
using System.Text;

var apiKey    = "oxy_abc123def456";
var apiSecret = "your_api_secret_here";

var method    = "GET";
var endpoint  = "/api/v1/products";
var timestamp = DateTimeOffset.UtcNow.ToUnixTimeSeconds().ToString();
var nonce     = Convert.ToHexString(RandomNumberGenerator.GetBytes(8)).ToLower();

var message   = $"{method}\n{endpoint}\n{timestamp}\n{nonce}";
using var hmac = new HMACSHA256(Encoding.UTF8.GetBytes(apiSecret));
var signature = Convert.ToHexString(hmac.ComputeHash(Encoding.UTF8.GetBytes(message))).ToLower();

using var http = new HttpClient();
http.DefaultRequestHeaders.Add("Authorization", $"Bearer {apiKey}:{signature}:{timestamp}:{nonce}");

var res = await http.GetAsync("https://panel.musteri.com/api/v1/products");
Console.WriteLine(await res.Content.ReadAsStringAsync());

5. En İyi Uygulamalar

  • Nonce tekrarlamayın. Her istek için yeni bir rasgele nonce üretin; aynı nonce reddedilebilir.
  • Timestamp güncel olsun. Mevcut saatten ±5 dakika dışında üretilmiş imzalar reddedilir.
  • HTTPS kullanın. HTTP üzerinden çalışan istekler üretim ortamında kapatılmıştır.
  • Secret'ı döndürün. Yılda en az bir kez API Secret değerini yenileyin.
  • Minimum yetki prensibi. Her entegrasyona sadece ihtiyacı kadar permission scope verin.
  • Logları maskeleyin. Authorization header'ı üretim loglarına yazılmamalıdır.

6. Cron Token (Planlı İşler)

Planlı senkronizasyon işleri (/cron/* endpointleri) farklı bir mekanizma kullanır. Cron isteklerinde HMAC yerine ayrı bir başlık gönderilir:

bashcurl -s "https://panel.musteri.com/cron/sync-orders" \
     -H "X-Cron-Token: your_cron_token_here"

Önemli. Cron token'ı sadece sunucu taraflı planlı görevlerde kullanın. Tarayıcıdan veya mobil uygulamadan çağırmayın.
